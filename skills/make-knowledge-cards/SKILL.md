# Make Knowledge Cards

## 概述

把用户粘贴的文章或本地 Markdown/TXT 文件转换为 5~8 张知识卡片。每张卡片只讲一个知识点，包含四个字段：标题、核心知识、简明解释、例子或自测问题。

## 输入处理

- **粘贴文本**：直接使用用户消息中的文章内容，无需其他步骤。
- **本地文件**：用户给出 `.md` 或 `.txt` 文件路径时，先读取文件全文再处理；读取失败时说明原因，不要凭文件名或记忆猜测内容。若 TXT 出现乱码，尝试改用 UTF-8 或 GBK 编码重新读取。
- **不支持的输入**：网页抓取、PDF、图片、Anki 卡片等均不支持。遇到此类输入，明确告知用户本 Skill 的边界，并建议其先将内容粘贴为文本或转成 Markdown/TXT。

## 工作流程

1. **通读全文**：理解文章主题与结构，区分核心知识（论点、概念、步骤）与铺垫、举例、重复论述。
2. **提取候选知识点**：列出文章真正传递的重要知识。判断标准：去掉它文章就失去价值；能被独立理解；属于新信息而非常识背景。
3. **去重合并**：同一知识点在文中多处出现（换说法、反复强调）时合并为一张卡片；删除铺垫、客套、重复论述与无关内容。
4. **筛选定稿**：只保留最重要且信息完整、有原文依据的知识点，按文章逻辑排序；候选多于 8 个时按重要性保留最关键的 8 个。不足 5 个时输出实际数量（最少 1 张），绝不凑数。
5. **逐张成卡**：按下方「卡片结构」填写，确保每个字段都只来自原文。

## 卡片结构

每张卡片包含四个字段：

### 标题
一句话概括该知识点，可直接读懂，如「沉没成本不是成本」。避免含糊表述（如「关于成本」）。

### 核心知识
用 1~3 句话陈述原文的核心论断，保留原文关键术语，不自行发挥。

### 简明解释
用更生活化的语言解释「为什么 / 怎么用」，帮助读者真正理解，控制在 2~4 句话。

### 例子或自测问题
二选一：优先使用原文给出的实例；原文没有实例时，设计一个能检验理解的自测问题并附简短答案或提示（答案必须能从原文推出）。

## 质量规则（硬性）

- **一张卡片只讲一个知识点**：某条内容包含两个独立知识点时拆成两张卡。
- **不编造**：任何字段不得超出原文信息。原文未提及的机制、数据、结论不得补充；自测问题的答案必须由原文可推出。
- **不凑数**：信息不足时输出少于 5 张卡，不用重复内容、无关内容或过度概括充数。
- **保留原文术语**：核心知识中的关键术语与原文一致，不擅自替换。
- **覆盖全文**：卡片集合按原文逻辑排序，覆盖文章的主要价值点。
- **语言一致**：卡片输出语言与原文一致（原文中文则用中文，原文英文则用英文）。

## 输出格式

使用 Markdown 输出，卡片之间用空行分隔：

```markdown
## 卡片 1：<标题>

**核心知识**：<1~3 句>

**简明解释**：<2~4 句>

**例子**：<原文实例，或「自测问题：……（答案/提示）」>
```

输出前检查：卡片总数在 1~8 之间；每张卡只含一个知识点；内容均有原文依据；无重复卡片。
